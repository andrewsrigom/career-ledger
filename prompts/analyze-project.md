# Analyze a configured project

Use `$career-analyze-project` for `<project-id>`.

Read the latest private scan, the configured project context, existing activities and workstreams, and relevant legacy drafts or initiatives. Inspect the project directly through the directory already granted to Codex.

Capture meaningful dated activities, classify the technical surfaces materially changed with normalized `domains`, then create or update the workstreams they advance. Represent full-stack work with both `frontend` and `backend`. Preserve evidence provenance and temporal progression, use the least promotional supported significance, and mark all unsupported outcomes as needing confirmation. Do not create public copy and do not modify `content/public/`.
